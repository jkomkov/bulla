# Answerability Network 0.1 preregistration

Frozen question: can separately implemented verifiers connect one accepted
provider receipt with a verifier-checked supplied-byte reference to a witnessed
history, an objective witness fork, a bounded
covenant remedy, and exact graph-relative recall without strengthening the
provider's substantive claim?

Success requires Python, standalone Node, and browser equality for all six
states; exact `2,500 / 5,000 / 2,500` recall; one replayable selected path;
joint observation before equivocation; open-challenge refusal; exact
authorization; model-identity refusal; semantic/presentation-root separation;
and no inference of provider execution, truth, rollback, custody, collection,
or funds movement.

Kill or narrow the claim if a UI stage changes a protected output, a fork
reaches an unrelated branch, incomplete ancestry clears, a bond improves trust
or truth, one head establishes equivocation, P3 reaches automatic recourse, or
any implementation disagrees on a protected field, or presentation data can
change or suppress a protected result.
